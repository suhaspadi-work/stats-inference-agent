Statistical Inference Agent — Build Blueprint

Reference document for the phase-wise build. Click a phase to expand it. Status is saved locally in this browser.
Governing principle: the model chooses and interprets; deterministic code computes. The LLM never does arithmetic or estimates a statistic itself — every number in a report comes from a tool call to real code (pandas / scipy / statsmodels), never from the model's own generation.

Design decisions locked in before build

AreaDecision
UsersAnalysts, stakeholders, and portfolio reviewers — one engine, two interaction modes
v1 ceilingHard tier (messy multi-file driver analysis), built in vertical slices: simple → medium → hard

Data accessHybrid — typed tools for inference, declarative reviewable operations for wrangling
Data modelHandles, not rows; immutable versions with lineage; every operation logged with impact
Model visibilityMiddle privacy tier by default — schema, types, value frequencies, format patterns; no raw rows
EvaluationSynthetic data with planted ground truth (correctness) + public/real data (process and robustness)
OrchestrationLikely LangGraph — explicit stages, plan-freeze checkpoints, approval interrupts
Model providerGroq (openai/gpt-oss-120b) via langchain-groq — verified with real token-budget testing after Gemini's free tier proved too rate-limited during the companion SQL project; Llama models were deprecated from Groq's catalog mid-search, landing on GPT-OSS instead
Decision auditabilityEvery method selection, wrangling choice, and classification carries a rationale, alternatives considered and rejected, and evidence — with later changes explicitly linked back (supersedes) to what they replaced and why
Privacy enforcementStructural, not just policy — a dedicated ModelSafeView type is the only shape of data any tool may return to the model

Notes on the plan as a whole

  • Phases 0–8 are the real foundation. Everything from Phase 9 onward mostly adds another method or tier onto a working skeleton — the heavy lifting is front-loaded.
  • No phase produces a number the agent generated itself. Every checkpoint explicitly compares against a direct library call (scipy / statsmodels), the same discipline used throughout the Text-to-SQL build.
  • This is a bigger build than the SQL agent — sixteen phases versus nine, and Phases 11–13 (hard tier) are genuinely difficult. Worth pacing across multiple sessions.
  • Synthetic data generation (Phase 3) is placed deliberately early, before any test-execution tools, so every later phase has ground truth to check against from day one — this is what makes rigorous evaluation possible later without retrofitting it.
  • Every consequential decision the agent makes must carry a rationale and alternatives considered — not just the final method choice (MethodDecision, Phase 1), but the wrangling approach (WranglingRationale, Phase 1) and the request classification itself (ClassificationDecision, Phase 6). If a later result doesn't turn out as expected, the record must show what changed and why the new approach is the better fit — this is what makes the agent's reasoning auditable rather than just its output.
  • The model is structurally prevented from seeing raw data (ModelSafeView, Phase 1) — tools are typed to return schema/frequency/pattern summaries only, never a DataFrame or raw rows, closing the privacy-tier design as an enforced boundary rather than a followed convention.
